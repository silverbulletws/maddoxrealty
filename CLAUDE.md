## Conventions

### Styling
- All colours, fonts, sizes and container widths are tokens in
`src/styles/global.css` under `@theme`. **Never write an arbitrary hex in a
component.** If a value isn't a token yet, add it as one.
- Note captured originals in a comment beside any value you adjust.
- Tailwind arbitrary values use underscore syntax:
`basis-[calc(20%_-_12.8px)]`, not the compressed form.

### File structure
- **One `.astro` file per page** in `src/pages/`, named for its URL — the
Pages list above already names the file each captured URL maps to. Never a
catch-all `[slug].astro` fed by a data blob: distinct hand-designed pages
don't survive one shared template, and the per-page conditionals pile up
until nothing can be changed safely.
- **Each major section of a page is its own component**, in a folder named for
the page. Sections appearing on more than one page live in
`src/components/` root instead.

```
src/pages/index.astro                imports + <Layout> + sections, in order
src/components/home/Hero.astro       outline SECTION 1
src/components/home/<Section>.astro  one file per SECTION in the outline
src/components/Header.astro          shared — every page
src/components/MenuItem.astro        shared — repeated item markup
```

- **Section boundaries come from the capture.** One `## SECTION n` in
`_source/pages/outline/<slug>.md` is one component. Name it for what it
holds, and note its origin at the top of the file
(`<!-- outline: <slug>.md SECTION 3 -->`) so the two can be checked against
each other later.
- The page file stays thin — imports, `<Layout>`, and the sections in
document order. It should read as the page's table of contents.
- **There is a floor.** Don't give a five-line band its own file; inline it in
the page. A section earns a file when it carries its own data array or runs
past ~40 lines. Twelve two-line components is worse than one long page.
- **A page may be as many files as it needs. A content entry is exactly one.**
Two different rules, split by the WordPress content type recorded per URL in
`site-map.json`.
- **`type: "page"`** — hand-built. One `.astro` in `src/pages/`, plus a
component per section. Break a complicated page up as far as is useful.
- **Every other type** (`post`, and every custom post type) — one Markdown
file per entry in `src/content/<collection>/`, all of them rendered by a
single route. Never one `.astro` per entry, never several entries in one
file. Adding one later is adding one file; see the per-type sections above.

### Content
- Page content lives as **data arrays in component frontmatter**, not inline in
markup. A price change should be a one-line edit.
- Repeated item markup becomes a shared component. Threshold: one use is a
coincidence, two is a pattern, **three is a component.** Don't componentise
earlier — indirection has a cost too.
- That threshold and the section rule above are separate. A **section** gets
its own file because it's a section, even used once; the three-use threshold
governs only the **repeated item markup inside one**.

### Links
- Internal links are **relative with a trailing slash**: `/2026-sold/`, never
the absolute WordPress URL. Set `trailingSlash: 'always'` in
`astro.config.mjs` to match what Google has indexed.
- External links get `target="_blank" rel="noreferrer"`.

### Performance
- Never animate `height`, `width`, `padding` or `margin` — layout properties
cost a reflow every frame. Use `transform` and `opacity`.
- Sticky/fixed elements overlaying scrolling content get
`transform: translateZ(0)` and `will-change: transform`.
- Use the converted `.webp` from `_source/images/`, with `width`/`height`
from `_source/images/_manifest.json` to prevent layout shift.

### Keyboard order and accessibility
Tab order follows reading order — left to right, top to bottom — **whatever
the live site does.** Builders often get this wrong (the mobile menu's links
before the logo, a hidden desktop menu still tabbable on phones, a CTA placed
first in the markup and floated right). Every rule here is markup and ARIA
only; **nothing visible changes**, so none of it is a faithful-copy deviation.

- **Source order is visual order.** Write the header in the order it reads:
logo → menu items left to right → phone / CTA → mobile toggle. Never recreate
the look with CSS `order`, `flex-direction: *-reverse`, grid placement or
absolute positioning that puts the DOM out of step with the screen.
- **No positive `tabindex`, ever.** Only `0` on a custom control and `-1`
on the honeypot or a programmatic focus target.
- **A "Skip to content" link is the first focusable thing on the page**,
pointing at `<main id="main">`. Visually hidden until focused
(`sr-only focus:not-sr-only`), so the design is untouched.
- **Anything not visible is not focusable.** A closed mobile menu, the
desktop menu at phone width, off-screen carousel slides and closed
dropdowns are hidden with `display: none`, `hidden` or `inert` — never
only `opacity: 0`, `visibility` transitions left half-done, or off-canvas
`translate`. If a builder served two copies of the menu, only one may be
tabbable at any width.
- **Menus are real lists in a labelled `<nav>`**: `<nav aria-label="Main">`,
`<nav aria-label="Footer">`, with `aria-current="page"` on the current
item. Dropdown children sit in the DOM straight after their parent.
- **Dropdowns work from the keyboard.** The parent stays a link; a
`<button aria-expanded aria-controls>` beside it (or the whole item, when
the parent has no page of its own) opens the submenu. Hover opens it too on
a mouse; Escape closes it and returns focus to the button, and it closes
when focus leaves it. Nesting comes from `shared.json` `navMenus`. The
starter's `Header.astro` already works this way — restyle it, keep its
structure.
- **The mobile menu toggle is a `<button>`** with `aria-expanded`,
`aria-controls` and an accessible name. On open, focus goes to the first
menu link; Escape and the close button return focus to the toggle.
- **Every link and button has a name.** Icon-only phone, email, social and
close links get an `aria-label` that says where they go ("Call (555)
123-4567", "Facebook"). Decorative icons get `aria-hidden="true"`.
- **Focus is visible.** Keep a `:focus-visible` outline (it shows for
keyboard users only, so mouse users see the original design). Never
`outline: none` without a replacement.
- Headings go in order (one `<h1>`, no skipped levels) — restyle a heading
tag with a class rather than picking the tag for its size. Form fields keep
their `<label>`; placeholder-only live forms get a visually hidden one.
- **`npm run build && npm run a11y` passes** before a page is called done.
It runs axe (Lighthouse's accessibility engine) at 1440 / 820 / 390 and
tabs through every page: the skip link must come first, nothing invisible
may take focus, and the header must tab in reading order. Tab through by
hand once as well. Colour contrast failures
that come from the client's palette are flagged in the notes, not fixed.

### Redirects (Cloudflare Pages)
`public/_redirects` is **not** `.htaccess`. It takes one rule per line —
`/from /to 301` — with `*` → `:splat` and `:name` placeholders, statuses
301/302/303/307/308, and `200` for a same-site rewrite. First match wins.
Limit: 2,000 static and 100 dynamic rules.

Never carry these over from `.htaccess`, the Redirection plugin or Yoast —
Cloudflare either ignores them or loops:
- Regex, `RewriteRule`/`RewriteCond`, `[L,R=301]` flags.
- **Query strings.** `/?p=123`, `/?page_id=`, `/?feed=rss2` can't be matched:
the query is ignored, so `/?feed=*` matches `/` and redirects the home page
to itself.
- Host and protocol rules — `www` ↔ apex, `http` → `https`.
- Any rule whose two sides are the same path.

Where those go instead: `http` → `https` is "Always Use HTTPS" on the zone;
`www` ↔ apex and query-string redirects are **Redirect Rules** in the
Cloudflare dashboard (Rules → Redirect Rules), which can match
`http.request.uri.query`. Only if the zone isn't on Cloudflare, use a Pages
Function (`functions/_middleware.js`) scoped with `_routes.json` to the
paths that need it, so every other request stays static. List anything moved
out of `_redirects` in the notes below so it gets set up at DNS time.

### Files over 25 MiB
Cloudflare Pages rejects any single file over **25 MiB**, and one such file
fails the whole deploy. `npm run check` (also run by `npm run build`)
lists anything over, or `find public -type f -size +24M`. Compress anything it finds in place —
**same filename**, so no URL changes — and keep the original out of git.
- **Video:** `ffmpeg -i in.mp4 -c:v libx264 -crf 26 -preset slow -vf "scale='min(1920,iw)':-2" -c:a aac -b:a 128k -movflags +faststart out.mp4`.
Add `-an` for a muted background loop. Step `-crf` up by 2 until it fits;
past 30 the loss shows, so stop there and look at it.
- **PDF:** `gs -sDEVICE=pdfwrite -dCompatibilityLevel=1.5 -dPDFSETTINGS=/printer -dNOPAUSE -dQUIET -dBATCH -sOutputFile=out.pdf in.pdf`.
Try `/ebook` only if `/printer` isn't enough, and check that small print
and scanned pages are still readable.
- Compare before and after, and report the sizes. **If a file can't get under
the limit without visible loss, stop and ask** — the options are a Cloudflare
R2 bucket, a YouTube/Vimeo embed, or splitting a PDF, and that is the
client's call, not a silent quality drop.
- Aim well under the cap: a 24 MiB hero video is a deploy that works and a
page that doesn't load on a phone.

## Faithful copy means faithful

Typos, odd capitalisation, dated copy and inconsistent prices are **preserved**.
They belong to the client. Flag them for a client email; don't fix them.

### The sanctioned exceptions

Deviate only where the original is broken rather than ugly. Get sign-off before
adding to this list.

1. **Form inputs pinned at 16px.** Below that iOS Safari zooms on focus. A bug,
not a design choice.
2. **Google Maps → embed iframe.** The Maps JavaScript API now needs a
billing-enabled key nobody can find. The iframe is free and keyless.
3. **Meta descriptions spelled correctly.** Invisible on-page, visible in search
results; no faithfulness argument for shipping a typo there.
4. **Genuinely broken content** — a page promising information it doesn't
contain, a link to nowhere. Fix and note it.

## Working style

- **Ask before guessing on layout.** The capture gives content and type
accurately; section arrangement is where errors happen. If
`pages/outline/` doesn't answer it, ask rather than build it twice.
- **Say when something is a guess** so it gets checked.

## Environment

- **Astro's dev server goes stale** after structural edits. Hard reload, then
restart `npm run dev`. Don't debug code that isn't running.
- Astro runs **one dev/preview server per project** (`npx astro dev stop`,
`npx astro preview stop`). Neither applies `public/_redirects`: the
`/sbws_property/` → `/property/` redirects only work on Cloudflare.
- First visit to a property page in dev is slow while its photos are optimised;
a full `npm run build` takes about 3 minutes (≈7,400 image variants).
- **Keep the project on a native Linux filesystem**, not a mounted Windows
partition — Vite's watcher is unreliable on NTFS and git reports phantom
permission diffs.
- `_source/` is **gitignored**: hundreds of MB of screenshots and originals.
